
# Alembic Commands Cheat Sheet

A practical reference for commonly used Alembic commands in Python projects using SQLAlchemy, FastAPI, and PostgreSQL.

## 1. Initialize Alembic

| Command                              | Description                            |
| ------------------------------------ | -------------------------------------- |
| `alembic init migrations`          | Initialize Alembic with sync template  |
| `alembic init -t async migrations` | Initialize Alembic with async template |

## 2. Generate Migrations

| Command                                                     | Description                                               |
| ----------------------------------------------------------- | --------------------------------------------------------- |
| `alembic revision -m "message"`                           | Create an empty migration file                            |
| `alembic revision --autogenerate -m "message"`            | Automatically detect model changes and generate migration |
| `alembic revision --autogenerate -m "add products table"` | Generate migration for a specific change                  |

**Important:** Always review autogenerated migration files before applying them.

## 3. Apply Migrations (Upgrade)

| Command                           | Description                                  |
| --------------------------------- | -------------------------------------------- |
| `alembic upgrade head`          | Apply all pending migrations                 |
| `alembic upgrade +1`            | Apply the next migration                     |
| `alembic upgrade +2`            | Apply the next two migrations                |
| `alembic upgrade <revision_id>` | Upgrade to a specific revision               |
| `alembic upgrade base`          | Upgrade to the base revision (usually no-op) |

## 4. Rollback Migrations (Downgrade)

| Command                             | Description                      |
| ----------------------------------- | -------------------------------- |
| `alembic downgrade -1`            | Roll back one migration          |
| `alembic downgrade -2`            | Roll back two migrations         |
| `alembic downgrade <revision_id>` | Downgrade to a specific revision |
| `alembic downgrade base`          | Roll back all migrations         |

**Warning:** Downgrading may delete tables, columns, and data depending on the migration.

## 5. Check Migration Status

| Command                        | Description                                                |
| ------------------------------ | ---------------------------------------------------------- |
| `alembic current`            | Show current database revision                             |
| `alembic history`            | Show migration history                                     |
| `alembic history --verbose`  | Show detailed migration history                            |
| `alembic heads`              | Show latest revision(s)                                    |
| `alembic branches`           | Show migration branches                                    |
| `alembic show <revision_id>` | Show details of a specific revision                        |
| `alembic check`              | Check whether model changes would generate a new migration |

## 6. Work with Specific Revisions

| Command                                             | Description                                                                |
| --------------------------------------------------- | -------------------------------------------------------------------------- |
| `alembic stamp head`                              | Mark database as being at the latest revision without executing migrations |
| `alembic stamp base`                              | Mark database as having no applied migrations                              |
| `alembic stamp <revision_id>`                     | Mark database at a specific revision without executing it                  |
| `alembic merge -m "merge branches" <rev1> <rev2>` | Merge two migration branches                                               |

**Important:** `stamp` only changes Alembic's revision tracking. It does not execute SQL or modify the database schema.

## 7. Useful Command Options

| Option             | Description                                     |
| ------------------ | ----------------------------------------------- |
| `--sql`          | Generate SQL instead of executing migrations    |
| `-x`             | Pass custom arguments to migration scripts      |
| `-c alembic.ini` | Specify a configuration file                    |
| `--autogenerate` | Detect schema changes using SQLAlchemy metadata |
| `-m "message"`   | Add a migration description                     |
| `--rev-id <id>`  | Specify a revision ID                           |

## 8. Common Development Workflow

For a FastAPI + SQLAlchemy + PostgreSQL project:

### Step 1: Modify SQLAlchemy Models

Add or update models, columns, relationships, indexes, etc.

### Step 2: Generate Migration

```bash
alembic revision --autogenerate -m "add products table"
```

### Step 3: Review Generated Migration

Check the generated file inside:

```text
migrations/
    versions/
        <revision_id>_add_products_table.py
```

Verify both `upgrade()` and `downgrade()` functions.

### Step 4: Apply Migration

```bash
alembic upgrade head
```

### Step 5: Verify Migration

```bash
alembic current
alembic history
```

### Step 6: Check for Missing Migrations

```bash
alembic check
```

## 9. Quick Reference — Most Used Commands

```bash
# Initialize Alembic
alembic init migrations

# Generate empty migration
alembic revision -m "message"

# Autogenerate migration
alembic revision --autogenerate -m "message"

# Apply all pending migrations
alembic upgrade head

# Rollback one migration
alembic downgrade -1

# Rollback everything
alembic downgrade base

# Check current revision
alembic current

# View migration history
alembic history

# Check latest revision
alembic heads

# Check for missing migrations
alembic check

# Mark database at latest revision without executing migrations
alembic stamp head
```

## 10. Important Concepts to Remember

| Command          | Responsibility                                                 |
| ---------------- | -------------------------------------------------------------- |
| `revision`     | Creates a migration file                                       |
| `upgrade`      | Executes migrations against the database                       |
| `downgrade`    | Reverses migrations                                            |
| `stamp`        | Changes migration tracking without executing schema changes    |
| `history`      | Displays migration history                                     |
| `current`      | Displays the database's current revision                       |
| `autogenerate` | Generates migration operations based on detected model changes |

## 11. Best Practices

1. Always review autogenerated migration files before applying them.
2. Never modify an already-applied migration in a shared or production environment.
3. Always implement both `upgrade()` and `downgrade()` correctly.
4. Test migrations on a development database before production.
5. Take database backups before running potentially destructive migrations.
6. Keep migration files committed to Git.
7. Avoid using `stamp` unless you understand the actual database schema and revision state.
8. Use meaningful migration names, such as `add_products_table` or `add_product_category_id`.
